KLC Room is a room booking system for the Ministry of Finance's training agency (BPPK). I built it during my MSIB Batch 6 internship, in a team of three. The role and process side is on [my work page](/work/frontend-ministry-finance).

## The problem

Ministry units across Indonesia booked classrooms, dormitories, labs, meeting rooms, and halls through an old PHP system. It was slow to use. The new system had to serve five kinds of users, from public visitors to a super admin.

## Decisions

### Design with the people who use it

The team assisted a design sprint led by BPPK stakeholders, with 20 to 30 Ministry employees. I think it wasn't held really well. We started well when we defined the problems. But we ended up designing the UI too quickly, because many of the older employees needed something to visualize what we had talked about.

After that I designed about 80% of the system in Figma, from stakeholder references, with booking patterns people already know.

### Dates stored in UTC, shown in the selected time zone

I don't really remember the exact bugs. We started by handling dates ourselves with the built-in Date object, maybe with some help from Intl. They only have a few date functions, but we kept using them because we didn't know packages for dates existed. It was my 6th semester, but the first five were only about learning to code, not real projects, so I knew very little about dependencies. Comparing dates by their raw values was really bad.

Then we converted every date to a Unix timestamp. That is easy to compare. But we always needed an extra step to convert it back, and we still had to handle time zones and locale. Then we found date-fns. It made comparing easy, and time zones and locale too, because everything is a function I can call on any date.

Bookings span several days, and Ministry units sit in different Indonesian time zones. So now every date is stored in UTC, converted for the selected time zone with date-fns, and all date math goes through it.

### Reusable components across five roles

Forms, multiselect, file upload, dashboards, and calendars were built once and reused. That keeps every role's pages consistent.

## A late request

A booking calendar was requested late in the build. It shipped with a minimum feature set, a calendar view that lists every booked room per date with its type and location. Stakeholders asked for more. But the team chose to finish what we had already built, so no feature was left half done.

## Result

We delivered all planned features in six sprints. We wrote test cases but never ran them, and I have no usage data.
